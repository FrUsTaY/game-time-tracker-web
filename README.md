# GameBacklogs

> ⚠️ **КРИТИЧНО ДЛЯ AI-АГЕНТОВ И РАЗРАБОТЧИКОВ (Ограничение платформы):**
> Категорически запрещено удалять директорию `.next` или её подпапку `.next/cache` (командами `rm -rf`, средствами Node.js или git clean).
> В среде GigaStudio директория `.next/cache` используется как точка монтирования изоляции `bubblewrap` (`bwrap`). При её удалении среда падает с фатальной ошибкой `bwrap: Can't find source path /app/base/.next/cache`, что приводит к вечной поломке превью и терминала. Очистка кэша Next.js не требуется!

Веб-приложение для ведения бэклога компьютерных игр: активные прохождения с учётом
времени, бэклог, вишлист, платформы, статусы — плюс умный помощник на GigaChat,
поиск игр через RAWG.io и облачный экспорт/импорт коллекции на Яндекс.Диск.

## Возможности

- **Обзор** — статистика: активные игры, часы за всё время и за неделю, размеры
  бэклога и вишлиста, прогресс коллекции, недавняя активность, быстрое «+1 ч».
- **Активные игры** — игры в прохождении: журнал сессий (дата + часы), прогресс
  от среднего времени прохождения, смена статуса.
- **Бэклог** — запланированные игры; перенос в активные одним кликом.
- **Вишлист** — игры, которые хочется купить; купили — переведите статус.
- **Пройденные** — архив с часами и личными оценками.
- **Статусы** — Играю / В бэклоге / Вишлист / Пройдено / Брошено, меняются
  с карточки, из карточки игры и в деталях.
- **Платформы** — PC, PlayStation, Xbox, Nintendo Switch и другие; поля даты
  выхода, среднего времени прохождения, Metacritic, личной оценки и заметок.
- **Giga-помощник** — чат с GigaChat, который знает ваш бэклог и статистику
  (переключатель «Учитывать мой бэклог»).
- **Настройки** — ключи API, проверка подключений, экспорт/импорт на
  Яндекс.Диск.
- **Боковое меню** — на десктопе постоянное, на мобильных — выезжающее;
  индикаторы подключения интеграций. Тёмная и светлая темы.

## Стек

- Next.js 16 (App Router) + React 19 + TypeScript
- Tailwind CSS 3.4 + shadcn/ui
- Хранение данных: локальный JSON-файл `data/games.json` (без внешней БД)
- API-интеграции: RAWG.io, GigaChat, Яндекс.Диск — только через серверные
  Route Handlers, ключи не попадают в браузер

## Быстрый старт

```bash
bun install
bun run dev
```

Откройте http://localhost:3000

### Ключи API

Самый простой способ — страница **«Настройки»** внутри приложения: вставьте
ключи и нажмите «Сохранить». Они запишутся в `data/settings.json`
(серверный файл, не коммитится).

Альтернатива — переменные окружения (см. `.env.example`, скопируйте в
`.env.local`). Сохранённый в настройках ключ имеет приоритет над переменной
окружения.

| Переменная | Назначение | Где взять |
| --- | --- | --- |
| `RAWG_API_KEY` | Поиск игр, обложки, даты, среднее время прохождения | https://rawg.io/apidocs (бесплатно) |
| `GIGA_API_KEY` | Умный помощник (чат) | https://developers.sber.ru/gigachat — ключ авторизации `client_id:secret` в Base64 (можно вставить и сырую пару, приложение закодирует само) |
| `YANDEX_DISK_TOKEN` | Экспорт/импорт коллекции | https://oauth.yandex.ru — токен с правами на Яндекс.Диск REST API |
| `GIGA_TLS_STRICT` | `1` — строгая проверка TLS для GigaChat | По умолчанию отключена: сертификаты GigaChat подписаны российским УЦ, которого нет в доверенном хранилище Node.js. Приложение отключает проверку только для хостов GigaChat |

Без ключей приложение полностью работоспособно: игры добавляются вручную,
RAWG-поиск, помощник и облако просто покажут подсказку «настройте ключ».

## Интеграции

### RAWG.io

- `GET /api/rawg/search/?q=…` — поиск игр (обложка, дата выхода, платформы,
  среднее время прохождения, Metacritic).
- `GET /api/rawg/games/[id]` — карточка игры; используется кнопкой
  «Обновить из RAWG» в деталях игры.

При добавлении игры через поиск RAWG поля подставляются автоматически.

### GigaChat

- `POST /api/giga/chat/` — пересылает историю чата в GigaChat, добавляя
  системный промпт со сводкой вашей библиотеки (статусы, часы, списки игр).
- `GET /api/giga/status/` — проверка ключа (страница «Настройки»).

Авторизация: OAuth по `https://ngw.devices.sberbank.ru:9443`, затем чат через
`https://gigachat.devices.sberbank.ru/api/v1/chat/completions`. Access-токен
кэшируется на сервере до истечения срока.

### Яндекс.Диск

- `GET /api/yandex/` — статус подключения (имя пользователя).
- `POST /api/yandex/ { action: "export" }` — выгрузка коллекции в файл
  `disk:/GameBacklogs/backlog-export.json` (полный снимок со сессиями).
- `POST /api/yandex/ { action: "import" }` — импорт: игры совмещаются по id,
  более новые версии заменяют старые, ничего не удаляется.

## Структура

```
src/
  app/
    page.tsx                 # Обзор
    playing/ backlog/ wishlist/ completed/   # Разделы коллекции
    assistant/               # Чат с GigaChat
    settings/                # Ключи API, экспорт/импорт
    api/
      games/                 # CRUD игр (+ учёт сессий времени)
      settings/              # Сохранение ключей (серверные, маскируются в ответах)
      rawg/                  # Прокси к RAWG.io
      giga/                  # Чат и статус GigaChat
      yandex/                # Статус, экспорт, импорт Яндекс.Диска
  components/                # Боковое меню, карточки, диалоги, чат, настройки
  hooks/use-games.ts         # Клиентское состояние коллекции
  lib/
    store.ts                 # JSON-хранилище data/games.json
    settings.ts              # Хранилище ключей data/settings.json (+ env)
    rawg.ts / giga.ts / yandex.ts   # Клиенты интеграций (server-only)
data/                        # Локальные данные (в .gitignore)
```

## API приложения

| Метод и путь | Назначение |
| --- | --- |
| `GET/POST /api/games/` | Список игр (фильтр `?status=`), добавление |
| `PATCH/DELETE /api/games/[id]/` | Обновление (статус, `addHours` + `sessionDate`, поля), удаление |
| `GET/POST /api/settings/` | Статус и сохранение ключей |
| `GET /api/rawg/search/?q=` | Поиск в RAWG |
| `GET /api/rawg/games/[id]/` | Карточка RAWG |
| `POST /api/giga/chat/` | Ответ помощника |
| `GET /api/giga/status/` | Проверка GigaChat |
| `GET/POST /api/yandex/` | Статус / экспорт / импорт |

## Безопасность

- Ключи API читаются только на сервере и маскируются в ответах API настроек.
- `data/` (база и ключи) добавлена в `.gitignore`.
- Импорт из облака проходит санитизацию каждой записи.
- Запросы к GigaChat идут через серверный Route Handler — ключ недоступен
  браузеру.
